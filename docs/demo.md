# 比赛演示流程

## 演示目标

用 5 到 8 分钟展示系统如何在智慧校园场景中完成无感身份认证、分布式多设备协同、AI 风险评估和管理员审计。

## 准备工作

1. 启动 Rust 后端：

```bash
cd backend
cargo run
```

2. 使用 DevEco Studio 打开 `frontend/`，运行 `entry` 模块。
3. 准备两个演示窗口或设备：手机布局和平板布局。
4. 测试账号：

| 角色 | 账号 | 密码 |
| --- | --- | --- |
| 学生 | student001 | 123456 |
| 教师 | teacher001 | 123456 |
| 管理员 | admin001 | 123456 |

## 演示步骤

### 1. 登录与 Dashboard

使用 `student001 / 123456` 登录，进入 Dashboard 数据看板。

重点说明：

- ArkUI / ArkTS 原生页面。
- 今日认证次数、最近认证状态、绑定设备、AI 风险引擎。
- 快捷入口覆盖无感认证、考勤、门禁、记录、设备管理、管理员页。

### 2. 设备可信度与分布式协同

进入设备管理页，展示已绑定设备。

重点说明：

- 手机作为认证发起端。
- 平板作为结果展示端。
- 设备可信评分、可信等级、OpenHarmony 版本、分布式角色。
- `DeviceTrustManager` 当前用规则模拟，后续可替换真实设备可信认证。

### 3. 无感认证流程

进入无感认证页，选择：

- 认证方式：可信设备认证。
- 校园场景：教室签到或实验室门禁。

点击“开始认证”。

重点说明：

- 流程进度：设备发现、身份核验、风险评估、结果同步。
- `DistributedDeviceService` 模拟设备发现。
- `RemoteAuthService` 模拟手机发起、平板同步结果。
- 风险输出包含 `riskScore`、`riskLevel`、`riskReason`、`suggestion`。

### 4. 异常行为检测

切换到蓝牙/近场认证，并选择实验室门禁场景，可说明系统会提高风险评分。

重点说明：

- 陌生设备。
- 夜间访问。
- 连续失败。
- 短时间多地认证。
- 弱认证方式。

### 5. 认证记录筛选

进入认证记录页，展示：

- 全部、成功、失败、高风险筛选。
- 状态标签和风险标签。
- 每条记录显示时间、地点、设备、方式、风险原因和建议。

### 6. 管理员异常看板

切换管理员账号 `admin001 / 123456` 登录，进入管理员页。

重点说明：

- 用户数量、认证次数、异常认证、绑定设备统计。
- 最近异常认证记录。
- 后端 `/api/risk/logs` 可用于审计和追踪。

## 答辩亮点总结

- 符合 OpenHarmony SDK 4.2+、DevEco Studio 6.0+、ArkUI / ArkTS 技术要求。
- 支持手机和平板两类设备布局。
- 保留 OpenHarmony 分布式能力接入接口。
- Rust 后端使用统一 API 返回格式。
- AI 风险评估具备规则引擎和真实模型接入扩展点。
